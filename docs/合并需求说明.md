# 合并需求说明（基础版）

本版本合并了两份需求文档：

- **A**：《面向多学科学习的 AI 知识管理与智能复习助手 — 需求分析文档》v1.0 及其软件设计文档（编号 FR-01–18、NFR-01–11、D1–D6）
- **B**：同学的《需求分析文档》V2.0（编号 FR-01–11、NFR-01–12、DC、BR）

下文用 A-FR-xx、B-FR-xx 区分来源。

## 1. 冲突与取舍

| 冲突点 | A 的方案 | B 的方案 | 本版做法 | 理由 |
| --- | --- | --- | --- | --- |
| 复习方式 | SM-2 自动排期（A-FR-15，高） | 不用固定间隔算法，计划由用户主导（B-BR-04）；卡片可选（B-FR-09） | 两套并存：知识点卡片按 SM-2；学习计划由用户主导，AI 只出草稿 | 卡片是“记忆”，计划是“安排时间”，对象不同、互不覆盖 |
| 笔记来源 | 手写或粘贴 Markdown，导入 .md | 上传多格式资料并解析，带出处 | 两个入口都保留：笔记页写 Markdown；资料页上传后整理成带出处的笔记 | 两种用法都常见 |
| 导出 | 单篇 .md、学科 ZIP | 单个离线 HTML | 单篇 .md + 多篇离线 HTML；学科 ZIP 暂不做 | 离线 HTML 能覆盖“整门课打包”的用途 |
| 单次 AI 输入 | 16000 字 | 20000 字符 | 16000 字，可在设置中修改 | A 有实测依据：笔记最长 15158 字 |
| 超时 | 无响应 60 s | 总时长 120 s | 两个都用：60 s 无响应或总计 120 s，先到先停 | 两个约束针对的情况不同 |
| “今天”的分界 | 凌晨 4 点（A-D5） | 本机日历日 | 复习和计划都按凌晨 4 点 | 统一口径，避免同一页面两个“今天” |
| API Key 位置 | 只存本机（A-D4） | 只在后端，不进前端（B-NFR-09） | 存本机后端数据库，前端只拿到掩码 | 同时满足两条 |

## 5. 验证

`cd backend && uv run pytest` 覆盖：AC-07（SM-2 五张卡片的间隔与 EF）、AC-14（凌晨 1:30 复习算前一天）、整理→采纳→撤销、提炼→入卡组→复习、回收站、检索、HTML 导出不含脚本、Key 不出现在接口返回中、非本机来源被拒绝、资料上传与格式拒绝、计划超预算校验。AI 部分用模拟的大模型接口测试，真实模型的效果还需要用自己的 Key 实测。
